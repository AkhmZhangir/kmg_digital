### `POST /api/chat`
Запрос:
```json
{
  "message": "Как по данным ГИС определяют положение ВНК?",
  "mode": "ask",                                   // ask | learn | practice | review
  "sources": ["latyshova"],                        // chapter.id из layer.json (или имя папки train_latyshova) и/или id загруженных
  "lesson": "latyshova.gis-interpretation-tasks",  // id текущего шага (nodes[].id), можно null
  "history": [{"role": "user", "text": "…"}, {"role": "assistant", "text": "…"}]   // последние 6 реплик учитываются
}
```
Ответ 200:
```json
{
  "answer": "Текст, формулы в $...$ (KaTeX), markdown-жирный **…** и списки «1.», «- »",
  "citations": [
    {"source_id": "latyshova", "source": "Практическое руководство…", "unit": "u101-01", "page": 101,
     "quote": "В случае четкой границы воды с нефтью без переходной зоны контакт определяют как подошву пласта высокого сопротивления",
     "match": "exact"}                             // exact | fuzzy — цитата проверена кодом по тексту книги
  ],
  "insufficient": false,     // true — в источниках ответа нет, модель так и сказала: показать как «нет в источниках»
  "unverified": false,       // true — ответ есть, но ни одна цитата не подтвердилась: плашка «не подтверждено книгой»
  "dropped_citations": 0,    // сколько цитат модели отброшено как ненайденные (для отладки)
  "task": null,              // в practice: {"question","answer","source_id","page","unit"} — ответ спрятать до «Показать»
  "followups": ["Как определяется положение ГНК?"],   // до 3 кнопок-подсказок
  "mode": "ask", "model": "gemini-3.5-flash", "context_used": 17
}
```
`page` — страница книги; ссылка в PDF как раньше: `chapter.pdf + '#page=' + (page - chapter.pdf_first_page + 1)`.
Для загруженных файлов `page` = 1 или из разметки `<!-- page N -->`.

### Загрузка источников
- `GET /api/sources` → `{"sources": [{"id","name","kind":"chapter|upload","units","pages","nodes","folder"}]}` — все собранные главы из `out/*/layer.json` + загруженные.
- `POST /api/sources` с `{"name": "notes.md", "text": "…"}` → 201 `{"id": "src-ab12…", "name", "kind": "upload", "units": N, …}`. Браузер сам читает TXT/MD (`file.text()`), шлёт текст; полученный `id` кладёшь в `selectedSources` и в `sources` чата. Хранится в памяти сервера до перезапуска.
- PDF и DOCX: пока **415 unsupported_type** («в работе»). Полная обработка главы в курс по-прежнему офлайн: `run.py all --chapter X` (≈4 мин на Gemini) → `POST /api/reload` подхватит новую главу без перезапуска.

### Ошибки
Всегда `{"error": {"code": "...", "message": "по-русски для пользователя"}}`:
| HTTP | code | когда |
|---|---|---|
| 400 | `bad_json`, `empty_message`, `message_too_long` (>4000), `bad_mode`, `no_sources`, `empty_source` | неверный запрос |
| 404 | `unknown_source`, `not_found` | нет источника / метода |
| 413 | `too_large` | тело > 5 МБ |
| 415 | `unsupported_type` | загрузка не TXT/MD |
| 502 | `bad_model_answer` | модель ответила мусором — можно повторить |
| 503 | `model_unavailable` | квоты/туннель — показать «модель недоступна, курс работает без чата» |
Ответ идёт 5–40 с (Qwen на CPU — до пары минут): нужен индикатор «тьютор думает» и блок кнопки отправки. Одинаковый вопрос в том же контексте отдаётся мгновенно из кеша.

### Активности, которые бэкенд уже отдаёт
В `layer.json` (без сервера): задания `single`, `multi`, `order`, `cloze`, `calc` (+ `book_tasks` с `ocr_bad`), карточки `cards`, глоссарий, связи `links`. Через чат: `task` в режиме practice (свободный ответ + эталон). Других типов пока нет.

## 2026-11-25 · запись 1 · роли и контракт

Привет. Команда обсудила план и решила так: ядро конвейера (учебный слой как граф понятий, LLM, проверка, задания, модуль проверки закладок, доменный пакет) делает Claude, фронтенд курса делаешь ты. Работаем параллельно и друг другу файлы не трогаем.

### Почему меняем текущий подход
Сейчас один узел равен одной странице. ТЗ требует другого, и за это даётся большая часть баллов (слой 15, курс 15, двойники 30):
- узел — **понятие**, узлы идут в порядке для новичка, ни один термин не используется раньше узла, где он объяснён;
- у узла есть тип трудности (8 типов), слои «механизм → практика → нюансы», заблуждение, «что это значит для данных», ИТ-аналогия с границей, связи с типами;
- у каждого утверждения есть дословная цитата, страница и пометка «наблюдение / вывод / допущение»; видно, что написал автор, а что модель;
- на главу нужно ≥15 заданий и ≥4 типа из 5 (один ответ, несколько ответов, порядок с перетаскиванием пальцем, пропуск, расчёт);
- 100% покрытие единиц главы (таблица покрытия).

Твой код не выбрасываем: `extract.py`, проверка цитат и чисел и курс без сервера — правильные идеи, я их переиспользую в ядре.

- Мой `run.py` вызывает только `render(layer, out_dir)`. Если в контракте чего-то не хватает, напиши в `TO_CLAUDE.md` — сам контракт не меняй.

1. **`render.py` + `web/`** по `contract/layer.example.json`. Путь: части → шаги в порядке `order`, время на шаг, прогресс, возврат к месту, где остановился (localStorage обернуть в try/catch).
2. **Страница шага** со всеми блоками из контракта: заголовок для новичка и название из книги рядом, суть, как это работает, по шагам, разбор примеров, цифры и условия, понятия, формулы (KaTeX положить локально в `web/vendor/`, не CDN), таблицы (с внутренней прокруткой), частая ошибка, что это значит для данных, аналогия с границей, задачи из книги, иллюстрации. Пустые блоки не показывать. У **каждого абзаца** «стр. N» и ссылка на PDF `#page=N`. Абзацы, написанные моделью, визуально отличаются от цитат автора. Слои «механизм / практика / нюансы» и ветка «глубже» сворачиваются.
3. **Задания пяти типов** (формат в контракте): `single`, `multi`, `order` (перетаскивание мышью **и пальцем**, pointer events, плюс кнопки ↑↓ для клавиатуры), `cloze`, `calc` (допуск `tolerance`). Проверка сразу, затем верный ответ и пояснение, ссылка на шаг и утверждение.
4. **Карточки** на все узлы с отметкой «знаю / повторить», с сохранением.
5. **Конспект**: суть каждого шага и выводы для данных, печать в PDF через `@media print`.
6. **Карта связей**: граф шагов из `links` (SVG, считается в JS, без внешних библиотек; подойдёт простая раскладка по слоям `order`).
7. **Требования интерфейса из ТЗ**: 390 px и 1280 px без горизонтальной прокрутки, текст от 16 px, строка ≈70 знаков, светлая и тёмная тема (`prefers-color-scheme` + переключатель), альтернативный текст, видимый фокус, переход к содержанию с клавиатуры, `prefers-reduced-motion`, ≤30 МБ на главу.
8. Метка происхождения на иллюстрациях (`provenance`) и подпись «перерисовано по рис. N, стр. M», если она есть.

### Правила
- Всегда `encoding="utf-8"` в `read_text`/`write_text`/`open`. Сейчас на Windows `build.py` падает с `UnicodeEncodeError`: у нас машина на Windows, Python 3.14, запуск через `py -3`.
- Перед пушем: `git pull --rebase`, прочитать `CLAUDE_TO_CODEX.md`.
- Префикс коммита: `[codex] ...` у тебя, `[claude] ...` у меня.
- Чужие файлы не правим. Нашёл баг у другого — пиши в handoff.
- Без внешних зависимостей во фронте (никаких CDN): курс должен работать офлайн.
